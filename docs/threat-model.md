# Threat model

## Assets

| Asset | Why it matters |
| --- | --- |
| IMSI, IMEI, MSISDN | Subscriber-identifying data. Correlating them identifies and locates a person |
| IMS credentials in the configuration document | Private user identity, P-CSCF, XCAP credentials. Enough to impersonate a subscriber in IMS |
| Provisioning tokens | Bearer credentials for a subscriber identity |
| OMA-DM passwords | Control over a device's management tree |
| The OTP send capability | Every OTP costs the operator money |
| The ability to set `VERS` | Setting `-2` fleet-wide switches RCS off on every handset |

## Attackers

| Attacker | Capability |
| --- | --- |
| Anonymous internet | Can reach the endpoint if it is open, send arbitrary parameters and headers |
| Malicious handset | Valid SIM, can attempt to provision as another subscriber |
| Network observer | Sees traffic if TLS is absent or terminated badly |
| Insider with log access | Reads CloudWatch Logs, ALB access logs, metrics |
| Cost attacker | Wants to drive SMS spend, not steal data |

## Threats and what is done about them

### T1 — Impersonating another subscriber

*Send `IMSI=` or `msisdn=` for someone else and collect their IMS credentials.*

A query parameter is a claim, not a credential. A request with only a claimed
identity gets an OTP challenge, never a document. Authentication requires a valid
token, an OTP delivered to the subscriber's own MSISDN, an identity asserted by a
trusted operator gateway, or a GBA bootstrap.
`tests/test_provisioning_service.py::test_bare_msisdn_parameter_is_only_a_claim`.

### T2 — Forged header enrichment

*Send `X-3GPP-Intended-Identity: +8210...` and be believed.*

Honoured only when `ACS_TRUSTED_PROXY_CIDRS` is non-empty **and** the peer is
inside it. Empty by default, so the mechanism is off. Behind an ALB the evaluated
address is the right-most `X-Forwarded-For` entry, because the ALB appends and
earlier entries are caller-controlled.
`tests/test_enrichment.py::test_forged_leading_forwarded_for_entry_does_not_grant_trust`.

### T3 — Stealing or replaying a token

Tokens are 256 bits of entropy, stored only as a SHA-256 digest, bound to IMSI and
IMEI, TTL-bounded, compared in constant time, and revocable individually or per
subscriber. A token presented from a different IMEI is refused. An invalid token
returns `511`, sending the client back to bootstrapping.

### T4 — Brute-forcing an OTP

Six digits, hashed with the MSISDN so a digest cannot be replayed against another
number, single use, TTL-bounded, at most `ACS_OTP_MAX_ATTEMPTS` verifications
before the challenge is destroyed, and `hmac.compare_digest` for comparison.

### T5 — SMS pumping

*Drive OTP sends to make the operator pay.*

Per-MSISDN cooldown, a daily cap per MSISDN, and a repeat of an identical bootstrap
request reuses the outstanding challenge instead of sending a second message. Over
the cap the answer is `429` with `Retry-After`. A CloudWatch alarm fires on OTP
volume. Deployment refuses `--allowed-cidr 0.0.0.0/0`.

Residual: an attacker with many MSISDNs can still spend money. Add a WAF rate-based
rule and an account SMS spending limit.

### T6 — Subscriber enumeration

*Ask about many IMSIs and see which are known.*

An unknown subscriber and an unresolvable identity both get `511` with an empty
body. The MSISDN web form shows the same page either way. A wrong DM password and
an unknown DM user produce the same `401` with a `Chal`.

Residual: response timing differs slightly between a store hit and a miss. Not
addressed.

### T7 — PII leaking into logs and metrics

This is the easiest thing to get wrong, because the identifiers arrive in the query
string and every default log format records it.

- uvicorn's access log is disabled in the Dockerfile and in `configure_logging`.
- Application logs route every field through `redact_mapping`; `imsi`, `imei`,
  `msisdn`, `otp`, `token`, `authorization` and friends are masked or
  HMAC-pseudonymised.
- Unkeyed hashing is refused: a 15-digit IMSI is brute-forceable, so `hash` mode
  requires a secret.
- Metric dimensions are `Environment` and `Outcome` only.
- ALB access logs are off by default; the template documents why.
- `tests/test_pii_logging.py::test_no_raw_identifier_appears_in_request_logs`
  asserts it against real captured output.

### T8 — Unauthorised administration

*Disable RCS for a subscriber, or read the subscriber list.*

The admin API fails closed: with `ACS_ADMIN_TOKEN` unset every route returns `503`.
There is no default token. The token is compared with `hmac.compare_digest`, and in
AWS it is generated by Secrets Manager and injected as a task secret, so it is
never in the template or an image.

Residual: a single shared bearer token, with no per-operator identity or audit
attribution. Front it with an identity-aware proxy for a real operations team.

### T9 — XXE and XML bombs

Both parsers (`omacp/writer.py`, `omadm/syncml.py`) run with `resolve_entities`
off, `no_network` on, `load_dtd` off and `huge_tree` off. The DM body is capped,
and outgoing documents are built with `lxml` rather than string templates, so
attribute escaping is always correct.

### T10 — Fleet-wide denial of service through configuration

*The worst thing this service can do to its own users.*

A `VERS` of `-2` tells every handset that receives it to delete its configuration
and not ask again. Mitigations:

- the catalogue is validated at startup and a malformed one fails the container,
  rather than degrading to an empty document that would switch RCS off;
- version bumps are monotonic; a non-positive stored value restarts at `1`;
- forced disable values are an explicit admin action against one subscriber, with
  the value validated against the known set;
- startup validation refuses configurations that are unsafe for the declared
  environment.

### T11 — Container compromise

Non-root UID 10001, no shell for the service user, read-only root filesystem in
the task definition, base image pinned by digest, no build toolchain in the runtime
stage, and no inbound path to the tasks except from the load balancer.

### T12 — Cleartext transport

The ALB terminates TLS 1.2/1.3 when a certificate is supplied. Without one, the
deploy script warns that the service is HTTP-only. Responses carry
`Strict-Transport-Security`, and the CSRF cookie is marked `Secure` on HTTPS.

Residual: the template permits an HTTP-only deployment. Deliberate, so the stack
can be exercised without a domain, and warned about at deploy time.

## Explicitly accepted residual risks

1. Response timing may distinguish a known from an unknown subscriber.
2. A single shared admin token, without per-operator attribution.
3. An attacker with many valid MSISDNs can still cause SMS spend.
4. No WAF in the default stack.
5. HTTP-only deployment is possible.
6. GBA is not real, so a client that only supports GBA cannot be provisioned.
7. 91 of 116 OMA-CP parameters are not cross-checked against a licensed spec
   edition, so a name could be wrong and a handset would silently ignore it.
